# Problem Validation

## Purpose

Problem Validation determines whether a meaningful customer problem exists before significant investment in product development.

The objective is to reduce uncertainty by replacing assumptions with evidence.

## Validation Pipeline

1. Define the customer.
2. Define the problem.
3. List assumptions.
4. Rank assumptions by risk.
5. Interview real customers.
6. Observe behaviour.
7. Test the smallest valid experiment.
8. Collect evidence.
9. Decide:
   - Continue
   - Iterate
   - Pivot
   - Stop

## Core Principles

- Validate the problem before validating the solution.
- Behaviour is stronger than opinion.
- Payment is stronger than behaviour.
- Multiple independent evidence sources are stronger than one.
- Every experiment should answer one important business question.

## Evidence Hierarchy

### Level 1 — Opinion

Examples:

- Compliments
- Likes
- Survey responses
- Feature suggestions

Useful for generating ideas, but not for validation.

### Level 2 — Behaviour

Examples:

- Existing workaround
- Previous purchases
- Time invested
- Repeated problem occurrence

Behaviour provides stronger evidence than predictions.

### Level 3 — Commitment

Examples:

- Beta application
- Demo request
- Data sharing
- Follow-up meeting
- Referral

Commitment demonstrates increasing customer interest.

### Level 4 — Economic Evidence

Examples:

- Deposit
- Pre-order
- Paid pilot
- Subscription
- Purchase

Economic evidence provides the strongest early validation.

## Customer Interviews

Objectives:

- Understand the customer's life.
- Discover existing workflows.
- Identify current alternatives.
- Learn customer language.
- Measure problem frequency.
- Measure problem severity.

Avoid asking:

- Would you buy this?
- Do you like this idea?
- Which features should we build?

Prefer asking:

- Tell me about the last time this happened.
- How do you solve it today?
- What is frustrating?
- What have you already tried?
- How much time or money does it cost?

## Validation Experiments

Possible experiments:

- Customer interviews
- Observation
- Landing page
- Prototype
- Concierge MVP
- Wizard of Oz MVP
- Demo video
- Pricing page
- Paid pilot
- Pre-sale

Each experiment should test one important assumption.

## MVP Standard

An MVP exists to learn.

Every MVP should define:

- Hypothesis
- Customer
- Metric
- Success threshold
- Failure threshold
- Decision

## False Validation

The following do not validate demand:

- Likes
- Followers
- Downloads
- Page views
- Compliments
- Feature requests
- Waiting-list signups alone

Validation requires behavioural or economic evidence.

## Product-Market Fit

Problem Validation is not Product-Market Fit.

Product-Market Fit requires evidence of:

- Retention
- Repeat usage
- Customer satisfaction
- Organic recommendation
- Willingness to pay

## Scaling Rule

Do not scale until:

- The problem is validated.
- The solution is validated.
- Product-Market Fit exists.
- Customer acquisition is repeatable.
- Revenue is repeatable.

## Founder Academy Standard

The purpose of Problem Validation is not to prove that an idea is correct.

The purpose is to discover whether sufficient evidence exists to justify further investment.
