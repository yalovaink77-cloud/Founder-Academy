# Solution Validation — Research Report

## Purpose

Solution Validation determines whether the proposed solution actually solves the validated customer problem.

Problem Validation asks:

"Does the problem exist?"

Solution Validation asks:

"Does this solution solve it well enough?"

These are separate stages.

## Core Principles

A solution is not validated because customers say they like it.

A solution is validated when customers:

- Use it.
- Continue using it.
- Prefer it over alternatives.
- Recommend it.
- Pay for it.

## Assumptions To Test

Typical assumptions include:

- Customers understand the product.
- The solution solves the intended problem.
- The workflow is simple.
- Customers complete important tasks.
- Customers return.
- Customers prefer it over current alternatives.
- Customers are willing to pay.
- The solution creates measurable value.

## Validation Methods

Possible experiments:

- Interactive prototype
- Clickable prototype
- Concierge MVP
- Wizard of Oz MVP
- Limited beta
- Paid pilot
- A/B test
- Feature experiment
- Usability testing

Each experiment should validate one assumption.

## Success Metrics

Useful measures:

- Task completion
- Activation
- Time saved
- Error reduction
- Retention
- Conversion
- Repeat usage
- Referral
- Payment

## False Validation

The following are weak evidence:

- Positive comments
- Compliments
- Downloads
- Feature requests
- Social engagement
- Long waiting lists

Behaviour is stronger than opinion.

## MVP Rule

Every MVP should answer one important product question.

The MVP ends when learning is complete.

## Customer Behaviour

Observe:

- Where users hesitate.
- Where users quit.
- Which features they ignore.
- Which features create value.
- Which workflows repeat naturally.

Behaviour is more reliable than interviews.

## Product-Market Fit Relationship

Solution Validation comes before Product-Market Fit.

A validated solution may still fail to achieve Product-Market Fit.

## Founder Academy Standard

A solution is validated only when repeated customer behaviour demonstrates that it creates meaningful value.

## Actionable Workflow

1. Select one assumption.
2. Build the smallest useful experiment.
3. Test with real users.
4. Measure behaviour.
5. Collect feedback.
6. Improve.
7. Repeat.
8. Decide:
   - Continue
   - Iterate
   - Pivot
   - Stop
