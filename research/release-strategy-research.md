# Release Strategy — Research Report

## Purpose

Release strategy defines how a product becomes available to users while controlling risk and maximizing learning.

A release is not only distribution.

It is a validation event.

## Core Principles

A strong release requires:

- Product readiness.
- Customer understanding.
- Clear positioning.
- Distribution.
- Measurement.
- Feedback loops.

## Release Approaches

### Internal Release

Purpose:

- Technical validation.
- Team testing.
- Infrastructure checks.

### Private Release

Purpose:

- Controlled customer feedback.
- Early validation.
- Risk reduction.

### Beta Release

Purpose:

- Wider real-world usage.
- Behaviour measurement.
- Product improvement.

### Public Release

Purpose:

- Broad adoption.
- Growth.
- Market expansion.

## Release Criteria

Before release:

- Core problem understood.
- Product provides value.
- Critical workflows work.
- Analytics installed.
- Support available.

## Measurement

Track:

- Acquisition.
- Activation.
- Retention.
- Conversion.
- Revenue.
- User feedback.

## Common Mistakes

- Releasing without measurement.
- Treating launch as success.
- Ignoring user onboarding.
- Scaling before retention.
- No rollback plan.

## Founder Academy Standard

A release is a controlled experiment that creates evidence for future decisions.
