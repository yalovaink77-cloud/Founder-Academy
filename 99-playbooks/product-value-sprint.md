# Product Value Sprint

## Purpose

Define the smallest product experience that creates meaningful customer value and produces evidence about the product hypothesis.

## Sprint Question

> What must the product do first to prove that it creates value for the target customer?

## Inputs

- Validated problem evidence.
- Customer research.
- Current product state, if one exists.

## Step 1 — Write the Value Hypothesis

State:

- Customer.
- Situation/problem.
- Desired outcome.
- Product promise.
- Why the product may be better than the current alternative.

Keep the statement testable.

## Step 2 — Define First Value

Identify the earliest meaningful moment when the customer receives the promised benefit.

Do not confuse:

- Account creation.
- App installation.
- Page views.

with value unless they genuinely represent the desired outcome.

## Step 3 — Map the Critical Journey

Map only the path required to reach first value:

```text
Discovery
↓
Start
↓
Core Action
↓
First Value
↓
Reason to Return
```

Identify friction and trust requirements at each step.

## Step 4 — Define MVP Scope

Classify work as:

### Must Prove

Required to test the core value hypothesis.

### Supports Proof

Helps users reach or understand value.

### Later

Useful but not required for current evidence.

Remove features that do not help prove the current hypothesis unless safety, legal, or essential operational requirements demand them.

## Step 5 — Define Success Evidence

Before execution, state what evidence would support or weaken the hypothesis.

Possible evidence:

- Users complete the core action.
- Users reach first value.
- Users return for the intended reason.
- Users choose the product over an alternative.
- Users pay or make another meaningful commitment.

## Step 6 — Identify Product Risks

Record:

- Usability risk.
- Trust risk.
- Technical risk.
- Safety/legal risk when relevant.
- Value risk.
- Adoption risk.

Prioritize by consequence and uncertainty.

## Step 7 — Founder Decision

Choose:

- Build/test current MVP.
- Reduce scope.
- Change value hypothesis.
- Return to customer/validation research.
- Stop.

## Required Outputs

- Value hypothesis.
- First-value definition.
- Critical journey.
- MVP scope.
- Success evidence.
- Main product risks.
- Founder decision.

## Exit Criteria

The founder can explain:

- What value is being tested.
- For whom.
- What the product must do.
- What can wait.
- How first value will be observed.
- What evidence would change the plan.

## AI Role

AI may:

- Analyze research.
- Challenge scope.
- Draft journeys and requirements.
- Identify assumptions and risks.
- Support implementation and verification.

Founder owns the product promise, priorities, risk acceptance, and final scope.
