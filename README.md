# Founder Academy

## Status

**Founder Academy v1: COMPLETE as a reusable founder operating system and core execution curriculum.**

This does not mean the Academy will never evolve. It means the v1 system now has a complete path from founder question → evidence → action → measurement → decision → learning.

See:

- `00-foundation/founder-academy-v1-definition-of-done.md`

---

## Purpose

Founder Academy is a founder operating system.

It is not a marketing course.

It is not a startup guide.

It is not a collection of business articles.

Its purpose is to build a repeatable system that transforms ideas and finished products into successful, sustainable businesses.

The ultimate goal is not one successful launch.

> The goal is a founder capable of launching successful products repeatedly.

---

## Scope

Founder Academy is product-independent.

It is designed to work with:

- Mobile applications.
- SaaS products.
- Websites.
- AI products.
- Affiliate businesses.
- Content businesses.
- Marketplaces.
- Future products and business models.

Products such as Lumora, PiercingConnect, Kuryele, Barber SaaS, Hack Me, and future projects are case studies and application environments, not the foundation of the Academy.

Every reusable framework must survive beyond one product.

---

## Mission

Build founder capability to:

- Validate ideas.
- Understand customers.
- Prepare and test products.
- Position products.
- Find distribution.
- Acquire first users.
- Launch products.
- Measure results.
- Price products.
- Generate revenue.
- Build retention and growth systems.
- Use advertising when the fundamentals are ready.
- Scale without losing quality.

---

## Core Philosophy

Founder Academy follows these rules:

- Think in systems, not individual products.
- Learn principles before tools.
- Validate before building.
- Build before scaling.
- Measure before optimizing.
- Growth without retention is failure.
- Every lesson should produce reusable output.
- Case studies are examples, not rules.
- AI increases founder leverage but does not own founder judgment.

The core transformation is:

```text
Knowledge
↓
Decision
↓
Action
↓
Measurement
↓
Learning
```

## Applying Founder Academy to a Real Project

Do not guess the starting point.

Use:

- `99-playbooks/project-startup-protocol.md`

Audit the project against lifecycle evidence, identify the earliest consequential gap, and run one matching playbook.

A technically finished product may still need validation, customer research, positioning, distribution, or measurement before launch/scale.

## Post-v1 Direction

Founder Academy should now be used, not endlessly redesigned.

The default loop is:

```text
Real Project
↓
Lifecycle Audit
↓
One Active Sprint
↓
Evidence
↓
Founder Decision
↓
Project Learning
↓
Improve Academy only when a reusable lesson emerges
```

Platform-specific tactics, policies, prices, algorithms, and interfaces should be researched at execution time because they change.

---

## Source-of-Truth Rule

When information conflicts, prefer current explicit founder decisions and current repository source-of-truth documents over old handoffs, chat history, or unverified research drafts.

Founder Academy is a living operating system, but changes should preserve decision history, verification, and reusable learning.
